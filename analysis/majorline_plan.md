# Majorline: έλεγχος του site και σχέδιο ενσωμάτωσης (24.11.2026)

Αφορά το https://majorline.eu (εκλογικές προβλέψεις). Ζητήθηκαν τρία: (1) τα δεδομένα του, (2) η μέθοδός του, (3) προγραμματισμένη εργασία που φέρνει νέα δεδομένα κάθε δύο μέρες. Οι κοινοί κανόνες του `NIKH_plan2.md` ισχύουν και εδώ.

Κατάσταση (24.11.2026, ενημέρωση): ο χρήστης αποφάσισε ότι δεν χρειάζεται άδεια. Ο fetcher έτρεξε μία φορά (εκτίμηση 22.11.2026, `analysis/majorline_runs.csv`, `analysis/majorline_parties.csv`) και το `.github/workflows/majorline.yml` τον τρέχει κάθε δεύτερη μέρα, ανοίγοντας PR όταν αλλάζουν τα CSV (επιλογή Α, §7). Το email του §3 δεν στάλθηκε. Η ασυμφωνία του P(≥3%) εξηγείται στο `NIKH.md` ενότητα 18.

## Συμπεράσματα με μια ματιά

- Το site δίνει **πιθανότητες και έδρες**, όχι δημοσκοπήσεις. Δεν έχει API ούτε CSV (το CSV είναι του Pro, που «έρχεται»). Τα δεδομένα είναι ένα αδόκιμο JSON που φορτώνει η ίδια η σελίδα: `/data/greece.json`.
- Οι δημοσκοπήσεις του (341 από 14 εταιρείες) είναι σχεδόν οι ίδιες με τις δικές μας (337 στο `nikh_polls.csv`). **Δεν προσθέτει δεδομένα δημοσκοπήσεων**· προσθέτει έναν ανεξάρτητο υπολογισμό πάνω στα ίδια δεδομένα.
- Η αξία του για εμάς είναι **έλεγχος** των δικών μας αριθμών. Ήδη φαίνεται μία ασυμφωνία: ίδιο επίπεδο ΝΙΚΗΣ (1,3% έναντι 1,38%), αλλά P(≥3%) 4,8% έναντι 0,3–0,6% δικό μας (§5).
- Νομικά: το `robots.txt` επιτρέπει τα πάντα, αλλά **δεν υπάρχουν όροι χρήσης ούτε άδεια**, και το repo μας είναι **δημόσιο**. Ανάγνωση και τοπική αντιγραφή για έρευνα: χαμηλός κίνδυνος. Δημοσίευση των αριθμών τους στο repo/site, ή χρήση σε πελάτες: χρειάζεται γραπτή άδεια (§3).
- Πρόγραμμα: **GitHub Actions `schedule:` με PR** (όχι Vercel Schedules, όχι commit στο main), αλλά ενεργοποιείται **μόνο μετά την άδεια** (§7).

### Η μέθοδος όπως δηλώνεται (`method.html`, `record.html`, πεδίο `method`)

1. Όλες οι δημοσκοπήσεις → τάση ανά κόμμα. Ο τρόπος επιλέγεται ανά χώρα με έλεγχο σε παλιές εκλογές: απλός μέσος των τελευταίων ή φίλτρο Kalman (βάρος σε πρόσφατες και μεγάλες). Για την Ελλάδα: `K3 poll trend, a = 0.9` (δεν εξηγείται τι σημαίνει).
2. Διορθώσεις μόνο με απόδειξη (π.χ. Γαλλία β΄ γύρος: οι δημοσκοπήσεις υπερεκτίμησαν τον RN 14 στις 14, η διόρθωση μισεύει το λάθος). Για την Ελλάδα δεν δηλώνεται διόρθωση.
3. Άλλη πληροφορία (οικονομία, προηγούμενα αποτελέσματα) μπαίνει μόνο αν βελτιώνει την πρόβλεψη σε παλιές εκλογές· οι περισσότερες ιδέες απορρίφθηκαν.
4. Πραγματικός εκλογικός νόμος, που πρέπει πρώτα να αναπαράγει τα επίσημα αποτελέσματα παλιών εκλογών (Ελλάδα: όριο 3%, μπόνους από 25%, 20 έδρες + 1 ανά 0,5%).
5. Monte Carlo 10.000 εκλογές: στις δημοσκοπήσεις προστίθεται τυχαίο λάθος ίσο με τα πραγματικά λάθη της χώρας σε παλιές εκλογές· περιθώριο U(0,4)% για νέο κόμμα.
6. Πιθανότητα = συχνότητα στις προσομοιώσεις.
7. Κλείδωμα της πρόβλεψης με SHA-256 πριν τις εκλογές και δημόσια βαθμολογία μετά.

Δηλωμένο ιστορικό: Ελλάδα, 7 εκλογές 2012–2023: πρώτο κόμμα, μπόνους και πλειοψηφία σωστά 7/7· τα εύρη «8 στις 10» κάλυψαν 85% των ποσοστών και 91% των εδρών. Σε 25 εκλογές (Ελλάδα, Ισπανία, Γαλλία) η εκτίμηση ήταν πιο κοντά από τη μέση μεμονωμένη δημοσκόπηση σε 21, αλλά **εξίσου ακριβής με τον απλό μέσο όλων των δημοσκοπήσεων**. Δηλαδή το πλεονέκτημα δεν είναι καλύτερο ποσοστό, είναι οι πιθανότητες και τα εύρη εδρών. Δεν ελέγχθηκε ανεξάρτητα.

### Ποιότητα σελίδας (σύντομα)

- Ισχυρά: `lang="el"`, ένα `h1`, landmarks (header/nav/main/footer), 98 χαρακτηριστικά aria, καμία εικόνα χωρίς `alt`· φόρτωση 68 ms (DOMContentLoaded 65 ms) από CDN· γραμματοσειρές από bunny.net (χωρίς logs, σύμφωνα με την πολιτική τους).
- Headers: CSP, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, nosniff, Referrer-Policy, Permissions-Policy.
- Αδύναμα: το CSP έχει `'unsafe-inline'` σε script και style· HSTS μόνο `max-age=86400` (1 ημέρα, χωρίς includeSubDomains/preload)· το HTML έχει `max-age` 30 ημερών (μπορεί να μείνει παλιό HTML με νέο JSON αν αλλάξει το σχήμα).
- Η πρώτη καρτέλα του browser κόλλησε μία φορά στη `greece.html` (το pane ήταν κρυφό)· σε νέα καρτέλα σε πρώτο πλάνο φόρτωσε κανονικά. Δεν επαναλήφθηκε, άρα δεν το χρεώνω στο site. Δεν έτρεξε Lighthouse.

### Όριο ελέγχου: το «αποτύπωμα» δεν επαληθεύεται

Το `run.sha256` (4517d470…) πρέπει να «κλειδώνει» την εκτέλεση. Υπολόγισα στον browser το SHA-256 των ακριβών bytes του `greece.json` (0763130e…) και τριών παραλλαγών (χωρίς το `run`, συμπαγές και με ταξινομημένα κλειδιά, μόνο το `run_id`): κανένα δεν ταιριάζει. Το hash αφορά ένα αρχείο που δεν δημοσιεύεται. Άρα η δήλωση «κανείς δεν μπορεί να την αλλάξει» δεν ελέγχεται από έξω με το δημόσιο αρχείο. Στον fetcher το κρατάμε μόνο για ανίχνευση αλλαγής.

## 6. Σχεδίαση του fetcher (`analysis/majorline_fetch.py`, πρωτότυπο γραμμένο)

- **Stdlib μόνο.** `urllib.request`, `urllib.robotparser`, `csv`, `json`. Γενικό User-Agent `elections-research-script/1.0 (public aggregate poll data)`, όπως το `polls_wiki.py`. Χωρίς επικοινωνία ή όνομα στο UA.
- **Αιτήματα:** `robots.txt` και `greece.json`, με `time.sleep(1)` ανάμεσα (το πολύ 1/s, 2 ανά τρέξιμο). Conditional GET με `If-None-Match` (ETag στο `data/majorline/state.json`): χωρίς νέα εκτίμηση απαντά 304 και δεν γράφεται τίποτα. `Accept-Encoding: identity`, για να μη χρειάζεται αποσυμπίεση zstd.
- **Αποτυχία χωρίς εγγραφή.** Αν λείπει κλειδί που διαβάζουμε, ή το `robots.txt` απαγορεύει το path, το τρέξιμο σταματά πριν γραφεί CSV. Νέα κλειδιά: μόνο προειδοποίηση.
- **Cache ακατέργαστων:** τα ακριβή bytes στο `data/majorline/raw/greece_<as_of>_<sha8>.json` (gitignored). Τα CSV ξαναχτίζονται από αυτά.
- **Έξοδος** δίπλα στο `nikh_polls.csv`, και τα δύο με upsert, ταξινομημένα, ώστε το ξανατρέξιμο να μη δίνει διαφορά:
  - `analysis/majorline_runs.csv`: `as_of, run_id, sha256, method, n_polls, single_party_majority, no_bonus, nd_pasok_151`.
  - `analysis/majorline_parties.csv`: `as_of, party, src, share, p_in, p_first, p_second, p_third_enough, seats_bonus, lo_bonus, hi_bonus, seats_nobonus, lo_nobonus, hi_nobonus`. Κωδικοί κομμάτων όπως στην πηγή (`ND, ELAS, PASOK, NIKI…`)· ο πίνακας αντιστοίχισης με τα δικά μας (`config.PARTY_SHORT`, στήλες του `nikh_polls.csv`) γράφεται μαζί με τον αναγνώστη.
  - Στο πρώτο τρέξιμο το `trend` δίνει 15 ιστορικές ημερομηνίες (`src=trend`), που αντικαθίστανται από γραμμή `src=run` της ίδιας ημερομηνίας.
- **Έλεγχος:** `--selftest` (offline, συνθετικό δείγμα): έγινε και πέρασε, μαζί με έλεγχο ότι το upsert είναι σταθερό και ότι η γραμμή `run` νικά την `trend`. `ruff` χωρίς ευρήματα με τους κανόνες του CI. Το δίκτυο δεν δοκιμάστηκε.

**Σύσταση: Α, με PR, ενεργοποιημένο μόνο αφού υπάρξει γραπτή άδεια (ή αν το repo γίνει ιδιωτικό).** Μέχρι τότε: τίποτα προγραμματισμένο· χειροκίνητο τρέξιμο τοπικά, όταν ο χρήστης δώσει ρητή άδεια λήψης (η επιλογή Γ είναι ο ενδιάμεσος τρόπος, αν θέλει αυτοματισμό πριν την απάντηση).

Κίνδυνοι και μέτρα:
- **Commit στο main:** κάθε push στο main γίνεται deploy στο Vercel και το CI δεν το εμποδίζει. Αν και το `analysis/` δεν δημοσιεύεται (`.vercelignore`), κάθε bot commit δημιουργεί deployment. Γι' αυτό PR (κλάδος `bot/majorline-ΗΜΕΡΟΜΗΝΙΑ`), όχι commit στο main. Προαιρετικό: `ignoreCommand` στο `vercel.json`, ώστε commits που αγγίζουν μόνο `analysis/` να μη χτίζουν (να επαληθευτεί στην τεκμηρίωση του Vercel πριν χρησιμοποιηθεί).
- **Αλλαγή σχήματος πηγής:** ο fetcher αποτυγχάνει δυνατά, το workflow κοκκινίζει, δεν γράφεται τίποτα.
- **Cron:** το `*/2` στην ημέρα του μήνα ξαναρχίζει από την 1η, άρα στο τέλος του μήνα δύο διαδοχικές μέρες· δεν πειράζει, γιατί χωρίς νέα εκτίμηση το τρέξιμο δεν αλλάζει τίποτα. Τα scheduled workflows τρέχουν μόνο από τον default κλάδο και μπορούν να καθυστερήσουν. Σε δημόσια repos απενεργοποιούνται μετά από ~60 ημέρες χωρίς δραστηριότητα (να επαληθευτεί).
- **Cache στο CI:** το `data/majorline/` κρατιέται με `actions/cache`, όχι με artifact (το artifact είναι δημόσιο).
- **Αυτόματο merge:** δεν ενεργοποιείται αν δεν το ζητήσει ο χρήστης.

Σχέδιο workflow (δεν υπάρχει στο repo· τα actions καρφώνονται με SHA όπως στο `ci.yml`):

```yaml
name: majorline-fetch
on:
  schedule: [{cron: "23 6 */2 * *"}]     # κάθε δεύτερη μέρα, 06:23 UTC
  workflow_dispatch:
permissions: {contents: write, pull-requests: write}
concurrency: majorline
jobs:
  fetch:
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@<sha>
      - uses: actions/setup-python@<sha>
        with: {python-version: "3.12"}
      - uses: actions/cache@<sha>
        with: {path: data/majorline, key: "majorline-${{ github.run_id }}", restore-keys: "majorline-"}
      - run: python -I -X utf8 analysis/majorline_fetch.py
      - run: python -I -X utf8 -m unittest discover -s tests
      - env: {GH_TOKEN: "${{ secrets.GITHUB_TOKEN }}"}
        run: |
          [ -z "$(git status --porcelain -- analysis/majorline_*.csv)" ] && exit 0   # τίποτα νέο: κανένα PR
          b=bot/majorline-$(date -u +%F)
          git switch -c "$b" && git add analysis/majorline_*.csv
          git -c user.name=github-actions -c user.email=github-actions@users.noreply.github.com commit -m "Majorline: νέα εκτίμηση"
          git push origin "$b" && gh pr create --fill --base main
```

Θέλει τη ρύθμιση του repo «Allow GitHub Actions to create pull requests». Το `git status --porcelain` πιάνει και τα νέα (untracked) CSV του πρώτου τρεξίματος.
